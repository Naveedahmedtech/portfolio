# FOOTER.md

## Purpose

The footer is the final resting state of the website.

It should provide:

* identity
* professional links
* direct contact
* resume access
* minimal navigation
* final location / availability context

It should feel **quiet, precise, and complete**.

Do not introduce new technical proof or another large CTA section here.

---


---

# Identity

Use:

```text
Naveed Ahmed
Backend / Product Engineer
```

Supporting line:

> Building backend systems, developer platforms, integrations, and AI-enabled products.

Keep it short.

Do not repeat the Hero paragraph.

---

# Navigation

Recommended:

```text
Work
Experience
Engineering
About
Contact
```

If Writing becomes a dedicated section/page:

```text
Writing
```

can replace or sit alongside `Engineering`.

Do not include every route simply because it exists.

---

# Professional Links

Use:

```text
GitHub ↗
LinkedIn ↗
Resume ↗
Email ↗
```

Links should be text-first.

Small consistent icons are acceptable.

Avoid giant social icons.

---

# Email

Make the email directly accessible:

```text
technaveedahmed@gmail.com
```

Use a real `mailto:` link.

Do not force users through a contact form.

---

# Availability

Optional small line:

```text
● Open to remote and international opportunities
```

Keep this visually muted.

Do not list individual target countries.

---

# Location

Use:

```text
Islamabad, Pakistan
```

No map is needed.

---

# Resume

Include:

```text
Resume ↗
```

The resume should open the latest public PDF.

Keep this easy to find but visually secondary to the main website content.

---

# Visual Style

The footer should use:

* top border or subtle surface shift
* generous whitespace
* subdued secondary text
* strong typography for the name
* restrained link hover states
* same dark technical theme as the website

Avoid:

* large gradients
* huge footer illustrations
* glowing backgrounds
* technology-logo walls
* oversized social icons
* another full-screen section

---

# Motion

The Footer should contain almost no narrative motion.

The Contact section already resolves the global motion system.

On entering the footer:

```text
movement slows
↓
background system becomes still
↓
footer content appears
```

Possible subtle interactions:

```text
link → arrow shifts slightly
text → gains contrast
```

Nothing more.

The visitor should feel that the walkthrough has finished.

---

# Transition From Contact

The Contact section may end with:

```text
Contact ●
        │
        │
────────────────────────
```

The line becomes the footer's top border.

This creates a natural ending without introducing another visual scene.

---

# Responsive Layout

Desktop:

```text
Identity              Navigation          Elsewhere
```

Mobile:

```text
Identity

Navigation

Elsewhere

Location / Copyright
```

Use generous vertical spacing.

Do not squeeze everything into tiny columns.

---

# Copyright

Use:

```text
© 2026 Naveed Ahmed
```

Prefer generating the year automatically if easy.

Do not add unnecessary:

```text
All rights reserved.
Made with ❤️
Built with Next.js
Designed and developed by me
```

The technology used to build the portfolio does not need to be advertised in the footer.

---

# Optional Small Signature

A very subtle final engineering detail could be:

```text
Build → Understand → Prove → Improve
```

or:

```text
Build → Understand → Measure → Improve
```

Use only if it fits the final visual composition.

Do not make it more prominent than the professional identity.

---

# Accessibility

Use semantic:

```html
<footer>
```

Requirements:

* real links
* keyboard-accessible
* visible focus states
* sufficient contrast
* descriptive link labels
* no icon-only links without accessible names

---

# What Not to Include

Do not add:

* newsletter form unless one actually exists
* fake availability calendar
* service pricing
* WhatsApp widget
* phone number as a major CTA
* testimonials
* technology list
* certifications
* site visitor counter
* "currently listening to"
* weather/location widgets
* decorative code snippets

The footer should close the site, not restart it.
